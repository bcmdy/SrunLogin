# SrunLogin.GUI 项目检查与优化建议

检查对象：`dotnet/SrunLogin.GUI` 及其依赖的 `dotnet/SrunLogin.Core`。

检查结论：当前 GUI 项目可以成功构建，已验证命令：

```powershell
dotnet build dotnet\SrunLogin.GUI\SrunLogin.GUI.csproj
```

构建结果为 `0` 警告、`0` 错误。但从 Python 脚本迁移到 WinForms/.NET 后，仍有一些会影响可维护性、运行稳定性和真实登录成功率的优化点，建议按下面优先级处理。

> 实施状态：P0 已完成。已新增 `.editorconfig` 固定 UTF-8 编码约束；`SrunPortal` 已补齐紧凑 JSON 序列化、`Accept-Language` 请求头和资源释放；已新增 `dotnet/SrunLogin.Wpf` 作为 WPF GUI，并复用 `SrunLogin.Core`。

## P0：优先修复

### 1. 固定源码编码与文档编码（已完成）

现象：用 PowerShell 读取部分 `.cs`、`.md`、`.py` 文件时出现中文乱码。虽然当前 .NET 编译通过，但乱码会影响审查、维护和后续脚本处理。

建议：

- 统一将源码、README、脚本文件保存为 `UTF-8`。
- 增加 `.editorconfig`，显式声明 `charset = utf-8`。
- 构建脚本和 README 中的中文注释重新保存，避免后续误判为代码迁移错误。

涉及位置：

- `dotnet/SrunLogin.GUI/MainForm.cs`
- `dotnet/SrunLogin.Core/Services/SrunPortal.cs`
- `README.md`
- `python/login.py`

完成情况：

- 已新增 `.editorconfig`，统一声明 `charset = utf-8`。
- 已更新根目录 `README.md`，说明当前 Python、WinForms、WPF 与 Core 项目结构。

### 2. 校验登录加密 JSON 与 Python 版字节级一致（已完成）

Python 版在登录加密前使用：

```python
json.dumps(info, separators=(',', ':'))
```

这会生成无空格的紧凑 JSON。C# 当前在 `SrunPortal.LoginAsync` 中使用默认 `JsonSerializer.Serialize(infoObj)`，默认格式可能包含空格：

```csharp
var infoStr = JsonSerializer.Serialize(infoObj);
```

SRun 登录签名对 `info` 和 `chksum` 的字节内容敏感，JSON 格式差异可能导致“程序能运行但认证失败”。

建议：

- 为 `JsonSerializer.Serialize` 指定紧凑配置，并补充一组与 Python 输出对比的单元测试。
- 测试应覆盖 `infoStr`、XXTEA 输出、自定义 Base64、HMAC-MD5、SHA1 `chksum`。

涉及位置：

- `dotnet/SrunLogin.Core/Services/SrunPortal.cs`
- `dotnet/SrunLogin.Core/Crypto/XXTea.cs`
- `dotnet/SrunLogin.Core/Crypto/SrunBase64.cs`

完成情况：

- 已将 `SrunPortal.LoginAsync` 中的登录 `info` JSON 改为紧凑序列化。
- 已补齐 `Accept-Language` 请求头。
- 已让 `SrunPortal` 实现 `IDisposable`，释放 HTTP 资源。
- 已新增 `dotnet/SrunLogin.Core.Tests`，覆盖 Base64、XXTEA、紧凑 JSON、HMAC-MD5、查询字符串顺序、响应解析、HTML 提取和格式化输出。

### 3. 使用 WPF 重构 GUI（已完成）

当前 GUI 基于 WinForms 手写控件和绝对坐标布局，`MainForm.cs` 中混合了界面创建、业务调用、配置读写、日志、托盘和循环检测逻辑。若后续继续扩展托盘状态、自动登录、循环检测、配置页、日志页等功能，WinForms 版本会越来越难维护。

建议将 GUI 层重构为 WPF：

- 新建 WPF 项目，例如 `SrunLogin.Wpf`，继续复用现有 `SrunLogin.Core`。
- 使用 MVVM 拆分视图和逻辑：`MainWindow` 只负责界面，`MainViewModel` 负责状态、命令和表单数据。
- 将登录、注销、查询、循环检测封装为异步命令，避免在窗口类中直接写大量 `async void` 事件逻辑。
- 配置、日志、托盘、循环检测拆成独立服务，便于单元测试和后续维护。
- 通过 XAML 布局解决高 DPI、字体缩放、控件重叠和窗口自适应问题。
- 保持配置和日志写入 exe 同级目录，这一点作为产品设计保留。

涉及位置：

- `dotnet/SrunLogin.GUI/MainForm.cs`
- `dotnet/SrunLogin.GUI/SrunLogin.GUI.csproj`
- `dotnet/SrunLogin.Core/Services/SrunPortal.cs`

完成情况：

- 已新增 `dotnet/SrunLogin.Wpf` 项目，复用 `SrunLogin.Core`。
- 已实现登录、查询、注销、帮助、配置保存、自动登录、托盘、单实例互斥体、循环检测和日志输出。
- 已更新 `dotnet/build.ps1`，默认发布 `SrunLogin.Wpf.exe`。
- 已确认配置文件 `config.json` 和日志文件 `app.log` 继续写入 exe 同级目录。

## P1：稳定性与用户体验

### 4. 目标框架建议降到稳定 LTS 或明确运行时要求（已完成）

当前 GUI 工程使用：

```xml
<TargetFramework>net10.0-windows</TargetFramework>
<LangVersion>latest</LangVersion>
```

如果目标用户没有安装 .NET 10 Windows Desktop Runtime，程序会无法启动。除非项目明确要求 .NET 10，建议使用稳定 LTS，例如 `net8.0-windows`。

建议：

- 若面向普通 Windows 用户，改为 `net8.0-windows`。
- 若保留 `net10.0-windows`，在 README 和发布包中明确运行时要求。
- 避免长期使用 `LangVersion=latest`，防止不同 SDK 构建行为不一致。

涉及位置：

- `dotnet/SrunLogin.GUI/SrunLogin.GUI.csproj:5`
- `dotnet/SrunLogin.GUI/SrunLogin.GUI.csproj:6`

完成情况：

- 已将 `SrunLogin.Core` 和 `SrunLogin.Core.Tests` 调整为 `net8.0`。
- 已将 `SrunLogin.GUI` 和 `SrunLogin.Wpf` 调整为 `net8.0-windows`。
- 已移除旧 WinForms 项目中的 `LangVersion=latest`。
- 已在 README 中明确 .NET 8 Windows Desktop Runtime 要求。

### 5. 拆分超大的 `MainForm.cs`

`MainForm.cs` 同时包含 UI 布局、托盘、配置、日志、登录流程、循环检测、格式化方法，文件体量过大，后续维护难度高。

建议拆分为：

- `MainForm.Layout.cs`：控件创建和布局。
- `MainForm.Tray.cs`：托盘菜单、关闭/恢复窗口逻辑。
- `MainForm.Config.cs`：配置读写。
- `MainForm.Logging.cs`：日志输出和文件写入。
- `MainForm.LoopDetection.cs`：循环检测。

涉及位置：

- `dotnet/SrunLogin.GUI/MainForm.cs:268`
- `dotnet/SrunLogin.GUI/MainForm.cs:848`
- `dotnet/SrunLogin.GUI/MainForm.cs:1118`

### 6. 优化 WinForms 缩放与布局

当前窗体使用 `AutoScaleMode.None`、固定窗口大小和大量绝对坐标。高 DPI、字体缩放、中文字体替换时，控件容易重叠或显示不完整。

建议：

- 使用 `AutoScaleMode.Dpi` 或 `AutoScaleMode.Font`。
- 使用 `TableLayoutPanel`、`FlowLayoutPanel` 或锚点/停靠布局。
- 高级面板展开不要直接修改窗体固定宽度，改为响应式布局或单独设置 `MinimumSize`。
- 输入框、按钮、日志区增加锚点，适配不同 DPI。

涉及位置：

- `dotnet/SrunLogin.GUI/MainForm.cs:130`
- `dotnet/SrunLogin.GUI/MainForm.cs:268`

### 7. 循环检测需要防重入与取消（已完成）

当前循环检测使用 WinForms `Timer`，`Tick` 中直接触发异步检查。若一次网络检测或登录超过间隔，可能出现并发重入。

建议：

- 使用 `SemaphoreSlim` 或 `_isChecking` 防止重复执行。
- 停止循环检测时取消正在运行的网络请求。
- 循环检测失败时增加退避策略，避免网络异常时频繁请求认证服务器。

涉及位置：

- `dotnet/SrunLogin.GUI/MainForm.cs:1132`
- `dotnet/SrunLogin.GUI/MainForm.cs:1161`
- `dotnet/SrunLogin.GUI/MainForm.cs:1219`

完成情况：

- WPF 主线已使用 `CancellationTokenSource` 停止循环检测。
- 已增加 `SemaphoreSlim` 防止检查任务重入。
- 已为连续失败增加退避，避免网络异常时固定频率连续请求认证服务器。
- WinForms 旧版作为过渡版本保留，不再继续投入结构性重构。

### 8. 日志轮转逻辑需要修正

当前 `EnsureLogWriter` 在日志文件超过 4096 字节后重新打开追加写入，但没有截断或切换文件名，因此文件超过阈值后会频繁关闭再打开，不能真正轮转。

建议：

- 使用固定大小滚动日志，例如 `app.log`、`app.1.log`。
- 或者启动时截断超过上限的日志。
- 程序退出时统一释放 `_logWriter`。

涉及位置：

- `dotnet/SrunLogin.GUI/MainForm.cs:1078`

## P2：协议与工程质量

### 9. `SrunPortal` 应实现资源释放

`SrunPortal` 内部持有 `HttpClient` 和 `HttpClientHandler`，但当前没有实现 `IDisposable`。GUI 中每次登录、查询、注销都会创建新实例，长期运行时建议释放资源。

建议：

- `SrunPortal : IDisposable`，释放 `HttpClient`。
- 或引入复用的 `HttpClientFactory` 风格封装。
- 对 GUI 短生命周期操作，优先实现 `using var portal = new SrunPortal(...)`。

涉及位置：

- `dotnet/SrunLogin.Core/Services/SrunPortal.cs:24`
- `dotnet/SrunLogin.Core/Services/SrunPortal.cs:41`

### 10. 补齐请求头与 HTTPS 兼容策略

Python 原脚本包含 `Accept-Language`，并关闭了 HTTPS 证书验证。C# 当前没有 `Accept-Language`，也没有对校园网自签名证书场景的处理。

建议：

- 添加 `Accept-Language: zh-CN,zh;q=0.9`，提高与 Python 版的一致性。
- 如果确实要兼容自签名 HTTPS，提供显式选项，不要默认关闭证书验证。
- 将请求头集中为常量或配置，便于对照 Python 版维护。

涉及位置：

- `dotnet/SrunLogin.Core/Services/SrunPortal.cs:46`
- `python/login.py`

### 11. 表单输入需要更强校验

当前 URL、AC ID、循环间隔、超时时间、Ping 主机均通过普通文本框输入，非法值会在运行时才兜底或报错。

建议：

- URL 使用 `Uri.TryCreate` 校验。
- AC ID、循环间隔、超时时间改用 `NumericUpDown`。
- Ping 主机只允许域名或 IP。
- 登录前显示一次性错误汇总，避免多次弹窗。

涉及位置：

- `dotnet/SrunLogin.GUI/MainForm.cs:472`
- `dotnet/SrunLogin.GUI/MainForm.cs:848`
- `dotnet/SrunLogin.GUI/MainForm.cs:1219`

### 14. GUI 与 Core 是否合并

可以合并，但需要先明确项目定位。当前 `SrunLogin.GUI` 通过 `ProjectReference` 引用 `SrunLogin.Core`，分层本身是合理的：认证协议、加密、模型、格式化逻辑放在 Core，界面和用户交互放在 GUI。这样更利于测试、复用和后续 WPF 重构。

适合合并的场景：

- 项目只作为一个 Windows GUI 小工具发布，不再保留命令行、库复用或多前端计划。
- 不准备新增独立测试项目，协议逻辑主要通过 GUI 手工验证。
- 希望减少工程数量，让发布、打开、维护路径更简单。

不建议合并的场景：

- 准备按 P0 建议使用 WPF 重构 GUI。
- 需要保留 Python 迁移对照测试，确保认证协议和加密逻辑稳定。
- 后续可能增加 CLI、服务模式、托盘守护进程或其他前端。

如果确认合并，建议做法：

- 将 `SrunLogin.Core` 下的 `Crypto`、`Models`、`Services`、`Utils` 目录迁移到 `SrunLogin.GUI`。
- 删除 `SrunLogin.GUI.csproj` 中的 `ProjectReference`。
- 保留命名空间结构，例如仍使用 `SrunLogin.Services`、`SrunLogin.Crypto`，避免大范围改名。
- 更新构建脚本和 README 中的项目路径说明。
- 合并后仍建议保留 `Services`、`Crypto` 等目录边界，不要把协议逻辑混入窗体或 ViewModel。

折中建议：若短期内要 WPF 重构，不要先合并到 WinForms 项目；更好的方式是保留 Core，新增 WPF GUI。等 WPF 版本稳定后，如果确认只维护单体应用，再评估是否把 Core 源码移动进 WPF 项目。
